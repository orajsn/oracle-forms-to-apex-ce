# 0.7.0: conversion-engine preview checkpoint

This is a reviewed source checkpoint, not an end-to-end readiness claim.
The product direction remains multiple projects, with multiple Forms modules
in one project producing one native APEX application/export.

## What is implemented

The new helper modules derive missing effective metadata from paired Oracle
exports, sanitize locally, bind selected code to exact sources, split analysis
into bounded linked sections, validate a complete proposed blueprint and retain
independent review receipts. The native renderer produces one APEXlang application
from explicitly synthetic metadata, with report/form pages and control items.

Existing UI routes and historical conversion profiles are preserved. Merely
installing this source does not activate the new helpers or register OPAF roles.
Guarded lab registration is an operator action; JSN identifiers are reference
scope, not portable customer defaults. Never replace them to bypass a guard.

## Evidence distinctions

| Check | Evidence level |
|---|---|
| Original FMB extraction and effective metadata | Actual local Oracle tooling; original hashes retained |
| Engine contracts and boundaries | Synthetic unit/integration regressions in a clean source snapshot |
| Model comparison | Actual small synthetic OPAF trial; not a real-file conversion |
| Native APEXlang | Actual offline SQLcl validation of an authored engineering candidate |
| Real file through FOX UI to imported app/download | Not established by this checkpoint |
| Business behavior accepted | Human review required; never manufactured |

The primary real-file engineering check accounts for 9 blocks, 222 items and
662 recognized objects. Its candidate maps 216 fields; six legacy buttons remain
explicit remediation. A field mapping is not implemented legacy behavior.
Default-property recovery does not prove database DDL, keys or constraints.
Zero unresolved inherited properties in a metadata whitelist does not mean
inherited trigger/library behavior is complete.

Redaction is conservative analysis preparation, not an anonymization certificate.
Technical identifiers can remain. Destination-specific user permission, fresh
source/receipt checks and independent review are still required. Masked values
are unknown; withheld units cannot be reconstructed or treated as translated.

## Remaining connected-flow work

1. Finish and check real-source OPAF understanding/review against the frozen input.
2. Connect these stages to the FOX project workflow with actionable errors and
   safe continuation, without replaying completed or uncertain operations.
3. Validate the actual resulting package, import under a new non-overwriting
   application identity and exercise authenticated native pages.
4. Export the exact application, state tested APEX/SQLcl versions and schema
   prerequisites, and make that package downloadable through FOX.
5. Perform the guarded deployment and final UI/browser acceptance.

Until those checks pass, do not advertise arbitrary FMB conversion, guaranteed
import, behavioral equivalence, production readiness or a customer-ready demo.
No new infrastructure, IAM/network changes or customer-tenancy deployment is
authorized by this checkpoint. Existing source, jobs and evidence stay preserved.
